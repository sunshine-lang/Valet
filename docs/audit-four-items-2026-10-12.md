# Valet 四项检查记录 · 2026-10-12

> 验收范围补充：用户随后确认当前仅接入阿里云百炼，其他供应商尚未对接。下文第 1 项保留为未来扩展的凭据边界问题，不作为当前百炼接入失败依据。后续的 Ego Lite 复测及截图所列模型接入另有记录。

结论：四项都有实现基础，但尚不能整体验收。真实模型当前可连接；定时任务已经落库并能跨进程恢复。需要先修凭据串用、文件保护绕过、首次重启重开工具和单次任务启动失败丢失，再完善追踪与导出。

Valet 是一个本地 Agent 工作台，后端负责模型调用、工具执行、确认和任务调度，前端展示会话与追踪。本次按单用户、单后端进程检查，不把多人或多进程部署当作当前验收条件。

检查基于 `main` 的 `8ebb33f` 及当前工作区。开始前已有的 `pyproject.toml`、`test_model_config.py`、`uv.lock` 修改和其他文档均未改动。本次检查只新增报告，复现代码和临时数据库保留在本机临时目录。

| 检查项 | 当前可用 | 验收判断 |
| --- | --- | --- |
| 密钥与模型配置 | `.env` 和数据库模型设置可用；当前百炼 `deepseek-v4.1-flash` 的最小连接探针成功；运行上限 900 秒、流空闲 90 秒 | 部分达标。跨供应商 Key 继承和百炼地址优先级有缺陷；Mock 模式展示不足 |

## 必须修复

### 1. P1：切换供应商时沿用上一家的 Key

模型设置将页面 Key 保存在单行配置中。保存时只要新 Key 为空，就无条件复制旧 Key，没有判断供应商是否改变。[保存逻辑](../services/agent-api/src/agent_api/api.py#L499)

复现：先保存百炼及一个假 Key，再切换到 OpenAI、Key 留空。实际模型请求的供应商和地址已变成 OpenAI，Key 仍是百炼的假 Key。全过程使用脚本模型，未把任何真实密钥发给其他供应商。

最小修复：只有供应商及凭据目标未改变时才保留旧 Key；供应商改变时使用新供应商环境变量或要求重新填写。测试连接和正式运行应共用同一套凭据解析规则。否则会用错凭据，并可能把旧凭据交给新的接口。

### 2. P1：上传目录的只读保护可以绕过

当前通过路径的 `uploads` 别名判断只读，没有按实际文件位置判断。[路径解析](../services/agent-api/src/agent_api/workspace.py#L78) · [写入检查](../services/agent-api/src/agent_api/workspace.py#L124)

复现：`/uploads/original.txt` 被阻止；同一文件改用 `.valet/sessions/{id}/uploads/original.txt`，先读取再写入，护栏放行，原文件确实被覆盖。只修改了临时目录中的测试文件。

最小修复：对解析后的真实路径统一判断是否位于受保护上传目录，并让 `write_file` 和 `str_replace` 共用判断。否则模型可破坏用户上传原件。

### 3. P1：带 `..` 的路径会跳过敏感文件检查

当路径向项目外逃逸时，解析函数直接返回 `outside=True`，没有继续检查 `.env` 等禁止访问名称。[提前返回位置](../services/agent-api/src/agent_api/workspace.py#L75)

复现：临时路径 `../outside/.env` 的 `denied` 为空；获得普通项目外文件访问授权后，能读取其中的假数据。完整绝对路径本应被敏感路径规则拒绝。此处的普通文件授权不应解除密钥禁止访问规则。

最小修复：规范化并解析实际路径后，再统一执行敏感路径检查，最后判断是否需要项目外授权。否则文件授权可以顺带打开密钥文件。

### 4. P1：第一次重启会重新打开已关闭的工具

启动时会为缺少种子标记的配置补开文件和技能工具；新建配置并保存开关时没有同时写入这些标记。[首次补开逻辑](../services/agent-api/src/agent_api/agent/runs.py#L293) · [配置保存](../services/agent-api/src/agent_api/api.py#L506)

复现：在新数据库保存 `enabled_tools=[]`，关闭应用再重新创建应用后，列表变成 `ls`、`read_file`、`write_file`、`str_replace`、`read_skill`、`create_skill`。这是新配置第一次重启的边界，并非每次重启都会重置。

最小修复：初始化新配置时标记当前配置版本；兼容迁移仅作用于确实需要迁移的旧配置，保留用户明确关闭的选择。否则用户以为写入已禁用，重启后权限却扩大了。

### 5. P1：单次任务启动失败后被永久消费

调度器先停用单次任务、清空下次时间、填写上次执行时间并提交数据库，然后才调用运行管理器。[任务触发顺序](../services/agent-api/src/agent_api/schedules.py#L253)

复现：让 `manager.start()` 抛出异常，实际创建运行数为 0，但任务已 `enabled=False`、`next_run_at=None`，上次执行时间已有值；下一次轮询不会重试。启动失败只写进日志，没有可查询的任务错误字段。

最小修复：成功持久化运行后再把任务标记为已启动；启动失败保存错误并保留可重试状态。否则一次临时故障就会静默丢掉单次任务。周期任务也会跳过本次并推进到下一档。

## 应当修复

### 6. P2：`.env` 中的百炼自定义地址没有按预期生效

凭据解析先取供应商目录默认地址，只有地址仍为空才读取 `DASHSCOPE_BASE_URL`；百炼目录地址本身非空。[地址解析](../services/agent-api/src/agent_api/llm/providers.py#L340)

复现：将环境配置地址设为国际地域地址，页面地址留空，最终解析仍为中国内地地址。此复现只调用解析函数，没有联网。

最小修复：明确使用“页面显式地址 → 对应环境地址 → 目录默认地址”的顺序。否则按 README 修改地域地址后，正式运行仍会访问另一个地址。

### 7. P2：工具时间线记录的是执行之后的落库耗时

执行层等所有工具返回后，才创建工具步骤并立即结束。[工具执行与追踪顺序](../services/agent-api/src/agent_api/agent/loop.py#L550)

复现：工具实际执行约 252 毫秒，步骤仅记录 2 毫秒，步骤开始时间还晚于工具结束时间；在工具运行中取消，运行状态为 `cancelled`，工具步骤数量却为 0。真实界面里也能看到搜索等工具只有 1～3 毫秒，但不能据此推断真实接口耗时。

最小修复：执行前创建每个工具步骤；完成、失败、超时、取消时分别关闭对应步骤，并为并发工具保留各自状态。否则无法用时间线定位慢工具，取消或崩溃时也缺少工具执行证据。

### 8. P2：`ls` 的权限判断忽略传入目录

`classify()` 遇到 `ls` 时把目标强制设为 `/`，而实际工具执行使用 `args.path`。[错误目标](../services/agent-api/src/agent_api/permissions.py#L46)

复现：列出项目外测试目录时，护栏返回 `allow` 且 `outside=False`；工具执行又报“项目目录之外，需要授权”。这条路径没有生成所需的确认卡片。

最小修复：`ls` 与其他文件工具一样，按传入路径执行共同的路径判定。否则用户既不能正常批准这次操作，完全访问模式也会遇到错误的执行上下文。

### 9. P2：追踪有 JSON 数据接口，尚无成品导出入口

现有 `GET /api/runs/{id}` 已返回运行和完整步骤，可手工保存为 JSON；这部分已经可用。前端详情页没有导出／下载按钮，服务默认使用 `NoopExporter`，仓库未实现 JSON 文件导出器或 Langfuse 导出器。[详情 API](../services/agent-api/src/agent_api/api.py#L469) · [空导出器](../services/agent-api/src/agent_api/tracing/exporter.py#L17)

最小修复：在详情页为现有脱敏 JSON 增加下载按钮即可满足当前简单导出需求；无需先接外部平台。否则排障记录仍需手动请求 API 保存。

### 10. P2：配置模型与实际 Mock 模式没有清楚区分

Mock／真实客户端在进程启动时决定，页面保存模型不会改变客户端类型。README 已说明需要重启，因此不应把这种切换方式本身描述成未实现。[启动模式](../services/agent-api/src/agent_api/main.py#L28)

缺口在展示：健康接口返回实际模式，但前端没有保存和展示它；追踪供应商与请求模型取配置值。[前端健康状态](../web/src/stores/sessions.ts#L30) · [追踪字段](../services/agent-api/src/agent_api/agent/loop.py#L332)

复现：Mock 模式下保存 OpenAI／`gpt-4o`，运行仍由 Mock 完成；追踪供应商是 `openai`、请求模型是 `gpt-4o`、响应模型是 `mock`、费用为 0。响应模型在展开属性后可查，但页面没有明确的实际运行模式标记。

最小修复：界面和快照明确显示实际模式、配置模型、响应模型，并提示模式变更需要重启。否则用户容易把模拟链路当成真实模型验收。

## 当前默认策略

以下是已验证的现状，不是建议方案：

| 动作 | 请求批准 `ask` | 默认辅助 `assist` | 完全访问 `full` |
| --- | --- | --- | --- |
| 项目内读取 | 自动 | 自动 | 自动 |
| 项目内新建或覆盖文件 | 自动；已有文件须先读取 | 自动；已有文件须先读取 | 自动；已有文件须先读取 |
| 联网搜索与天气 | 首次确认；本对话授权后可自动 | 自动 | 自动 |
| 普通项目外读写 | 按读／写类别确认 | 按读／写类别确认 | 自动 |
| 工具自身显式要求确认 | 确认 | 确认 | 确认 |
| 未启用工具 | 拦截 | 拦截 | 拦截 |

敏感路径和只读上传在设计上应始终拦截，但当前存在第 2、3 项绕过。工具设置页写着“文件只写在当前会话的目录里”，实际文件工具能写整个项目根目录，说明文字应随策略修正。[界面说明](../web/src/views/SettingsView.vue#L212)

如果目标是首次使用时避免自动搜索和改项目文件，建议默认采用联网确认，并把项目源码写入与 `/outputs` 交付物写入分开授权。这是后续策略建议，本次没有修改默认行为。
